SigardaPanel v1.7.1

Fix
- v1.7.0's web bundle was packed with owner-only permissions (drwx------), so after installing as root the panel's web service (user sigardapanel) could not read it. The update failed its health check and rolled back. The bundle is now world-readable, and the installer makes the web directory readable whatever modes an archive carries.

Includes everything in v1.7.0 (panel self-update, agent updates, site operations on the site's agent, backup/restore improvements, security fixes). See the v1.7.0 notes.

Upgrade notes
- Signing key. Releases from v1.7.0 on are signed with a new minisign key:
  RWRuJBU1HM8C+XuaO7KjjPf1Bzwjara6ujA7FnHpqlbVIT6J/QGMC6BM
  Panels running v1.6.2 or older, including those that rolled back from a failed v1.7.0 update, still trust only the previous key, so their one-click or automatic update fails its signature check and changes nothing. Update them once by hand:
    curl -fsSLO https://raw.githubusercontent.com/bayurstarcool/SigardaPanel/main/install.sh
    sudo bash install.sh update
  Later updates, and agent updates started from the panel, work automatically again.
- Update the agent on every server after upgrading the panel. Older agents do not enforce IP allowlists; the panel warns about this.
- Rotate the password once for older database users that have no password stored in the panel, so that restores can import their databases.
- Cron jobs created before v1.7.0 were stored but never installed: delete and re-create them.

Install with the script in the repository README; every file is signed (see "Verifying releases").
