SigardaPanel v1.15.0

Import databases that already exist on a server.

- Databases → "Import existing" (super admin): pick a server (the panel host by default) and the panel lists the MySQL/MariaDB and PostgreSQL databases that exist on it, with owner and size; databases already in the panel and names the panel does not support are shown but cannot be chosen. Pick one, the site to attach it to, and optionally the application's database user and password.
- Given credentials are checked by signing in to the database on the site's server before anything is stored; a refused login is reported and nothing is imported. The account is stored encrypted, like the panel's own database users, and is then used by the database manager, backups and phpMyAdmin.
- Imported databases are marked "External" and are never changed on the server: removing one (or one of its users, or its site) removes only the panel records, never the database, its data or its accounts. Changing the character set, adding or granting users, changing a user's host or privileges and resetting passwords are refused for them (a new password would break the application). Any database or database-user job for an external database fails at once with "external database" and never reaches the agent.
- Databases created by the panel work as before. The older automatic import (POST /api/v1/database-server/import, which matches MySQL databases to sites by name) is unchanged.

Update the agents on remote servers after updating the panel (Settings → Panel update → Agents): listing a remote server's databases needs the new agent.

Panels on v1.6.2 or older must update once by hand because of the new signing key (see the v1.7.1 notes):
  curl -fsSLO https://raw.githubusercontent.com/bayurstarcool/SigardaPanel/main/install.sh
  sudo bash install.sh update

Install with the script in the repository README; every file is signed (see "Verifying releases").
