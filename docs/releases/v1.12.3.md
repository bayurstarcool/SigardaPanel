SigardaPanel v1.12.3

Every site runtime runs out of the box, on ports that never collide, and SSL waits for DNS.

- Node.js, Python, Go and Docker sites get a port in 30000-40000 that is unique in the panel and free on the site's own server (the agent reports which ports are in use there); sites created at the same time never get the same port.
- Changing an app's port is refused when another site or service uses it, with a free port suggested; a running app moves to the new port.
- Apps start right after the site is created. Go apps are built (go build) on start, restart or deploy when the binary is missing; before, new Go sites answered 502.
- Starters listen on 127.0.0.1 only and read $PORT, so apps are reached through nginx (TLS, access rules) and not directly on their port. Unchanged starters written by older panels (Node.js and Go listened on all interfaces) are replaced the next time the app starts or restarts; code you changed is left alone. Docker containers are published on 127.0.0.1.
- SSL: a new certificate waits (up to 45 minutes) until the domain resolves in public DNS before asking Let's Encrypt, so a just-created record no longer fails with NXDOMAIN. Failures caused by DNS still propagating are retried, and errors are shortened to the cause (missing record, port 80 unreachable, rate limit, ...).

Update the agents on remote servers after updating the panel (Settings → Panel update → Agents).

Panels on v1.6.2 or older must update once by hand because of the new signing key (see the v1.7.1 notes):
  curl -fsSLO https://raw.githubusercontent.com/bayurstarcool/SigardaPanel/main/install.sh
  sudo bash install.sh update

Install with the script in the repository README; every file is signed (see "Verifying releases").
