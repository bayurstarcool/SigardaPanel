SigardaPanel v1.11.2

Safer site deletion, Cloudflare DNS that never overwrites records you did not ask it to, and a live view of a new site's setup.

New site setup
- After you create a site, its page shows each stage with its state: site registered, server setup (Linux account and folder, PHP-FPM pool, Nginx vhost), Cloudflare DNS, SSL certificate, live. It updates while work is running and shows errors and retries.

Deleting a site
- The delete dialog lists what is always removed (vhost, PHP pool, databases, cron, SSH accounts) and has an option to also delete the site's files; by default the files stay (API: DELETE /api/v1/sites/:id?delete_files=false, CLI: site delete --keep-files).
- The DNS outcome of a deletion is shown; a record that could not be removed in Cloudflare is reported so you can remove it there.

Cloudflare DNS
- Records are created, updated and removed automatically, and only the ones the panel created: they carry the comment "SigardaPanel site:<id>" and are tracked per site. Records that already existed, or were changed in Cloudflare since, are never changed or deleted.
- An existing record for the same name that points elsewhere (A, AAAA or CNAME) is reported as a conflict and left alone, unless you choose "Replace existing DNS records" when creating the site, or "Replace with this server" on the site page (only the records you saw in that dialog are replaced). A correct existing A record is kept; the new record is created before old A/AAAA records are removed; every deletion is in the audit log.
- The site page has a DNS card: check, create, sync after a server IP change, replace.
- DNS always uses the site owner's Cloudflare account; only the owner or a super admin can change the records. After a transfer the panel stops managing the old owner's records.
- Zone matching fixed: the longest matching active zone at a label boundary (sub-zones, .co.id and other .id domains work; myexample.com no longer matches example.com).
- Records only point to a public IPv4. The panel host's entry on the Servers page now gets its public IP automatically when it held a private one (cloud VMs only see 10.x / 172.16.x on their interfaces); for other servers with a private address the agent detects the public one. An address set by hand always wins.

Update the agents on remote servers after updating the panel (Settings -> Panel update -> Agents).

Panels on v1.6.2 or older must update once by hand because of the new signing key (see the v1.7.1 notes):
  curl -fsSLO https://raw.githubusercontent.com/bayurstarcool/SigardaPanel/main/install.sh
  sudo bash install.sh update

Install with the script in the repository README; every file is signed (see "Verifying releases").
