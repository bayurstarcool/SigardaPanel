SigardaPanel v1.7.4

Impersonation survives a page reload
- "Login as" a user ended on every refresh: the impersonation token was kept only in page memory, so a reload silently switched back to the admin (while the page could still show the user's name). The panel's web server now keeps it in an HttpOnly, SameSite=Strict cookie, like the normal session, so it is never readable by page JavaScript. The "Viewing as" bar and the user's view stay after a reload until "Kembali" is pressed or the impersonation session expires (24 hours).
- An impersonation session that expired or was revoked is dropped on the next page load, and the admin's own session takes over again.
- Starting and stopping an impersonation reloads the page, so menus and the sidebar usage belong to the account being viewed.

Panels on v1.6.2 or older must update once by hand because of the new signing key (see the v1.7.1 notes):
  curl -fsSLO https://raw.githubusercontent.com/bayurstarcool/SigardaPanel/main/install.sh
  sudo bash install.sh update

Install with the script in the repository README; every file is signed (see "Verifying releases").
