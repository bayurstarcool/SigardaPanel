SigardaPanel v1.7.2

Disk usage and per-user disk limits
- Disk usage was always 0: it was measured inside the panel's sandboxed API process, which cannot see /home or sites on other servers. It is now measured by du on each site's server, through its agent (cached for 5 minutes, at most 8 measurements at a time). Sites whose server cannot be reached are reported as not measured instead of counting as 0, and the total is shown as a lower bound ("≥").
- The user page read field names the API never sent, and a site both owned and assigned to a user was counted twice. Both are fixed. The site page now shows the site's disk usage.
- Disk limits are enforced. A user's limit (GB) applies to the sites they own. At or over the limit the panel refuses actions that add data: creating sites, file manager writes, creates, uploads and compress, git deploys (also by webhook), git checkout/rollback, backup restores, and transfers to that user. Transfers also check the new owner's max sites. Sites stay online, and backups are never blocked.
- Every 5 minutes the panel checks usage, and notifies the user and the admins at 80% and 100%.
- The user create and edit forms can set the disk limit and max sites.

Notes
- Writes made outside the panel (SSH/FTP, cron, the site's own PHP) cannot be blocked. They show up in the 5-minute check and its notifications.
- Databases are not counted: MySQL data is not stored in the site's folder.
- Usage in the sidebar is now the sites the signed-in user owns, also for admins (it used to be every site on the panel for admins).
- Measuring needs the site's agent: update the agent on every server after upgrading the panel.

Panels on v1.6.2 or older must update once by hand because of the new signing key (see the v1.7.1 notes):
  curl -fsSLO https://raw.githubusercontent.com/bayurstarcool/SigardaPanel/main/install.sh
  sudo bash install.sh update

Install with the script in the repository README; every file is signed (see "Verifying releases").
