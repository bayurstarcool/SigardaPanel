SigardaPanel v1.15.1

The agent keeps the right to run commands as other accounts on hardened systemd hosts.

- With systemd 255, an agent unit that says User=root together with NoNewPrivileges and a seccomp option (LockPersonality, SystemCallArchitectures, ...) starts the agent without CAP_SETUID. Every task that runs a command as another account then fails with "operation not permitted": PostgreSQL through the postgres account (databases, users, the database manager), git deploys as the site owner, the site terminal and database restores.
- New installs (panel host and the remote agent install command) no longer write User=root; root is the default user of a system service, and Environment=HOME=/root keeps root's ~/.my.cnf for the MySQL client.
- Existing installs are fixed by the update itself: updating the panel (one click or install.sh update) and updating a remote agent (Settings → Panel update → Agents) replace User=root in /etc/systemd/system/sigardapanel-agent.service and reload systemd before the agent restarts. Nothing else in the unit changes.

Update the agents on remote servers after updating the panel (Settings → Panel update → Agents).

Panels on v1.6.2 or older must update once by hand because of the new signing key (see the v1.7.1 notes):
  curl -fsSLO https://raw.githubusercontent.com/bayurstarcool/SigardaPanel/main/install.sh
  sudo bash install.sh update

Install with the script in the repository README; every file is signed (see "Verifying releases").
