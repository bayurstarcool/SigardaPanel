SigardaPanel v1.16.1

Security and reliability fixes from a full feature audit.

- Security (critical): a database user created for a site could carry the name of an account that already existed on the database server. For PostgreSQL the panel then reset that account's password, so anyone allowed to manage a site's databases could create a user named "postgres" and sign in as the PostgreSQL superuser (and so read every site's database). The panel now refuses the server's own account names (postgres, pg_*, and the MySQL system accounts) and any name that already exists on the database server, and the agent refuses on its own to take over an existing account that has server-wide powers or is not a user of that database, or to drop such an account. Password rotation of the panel's own users works as before.
  If you run PostgreSQL databases: check that no database user named "postgres" or "pg_..." appears under Databases → Users; remove it there (only the panel record is removed) and, if one existed, set a new password for the postgres role or remove it (ALTER ROLE postgres PASSWORD NULL).
- Backups: downloading a backup stored in the site's folder failed ("backup file not found on disk"): the API process cannot see /home on the panel host, and backups of sites on other servers were never on the panel host at all. The site's agent now streams the file (opened so that a symlink cannot lead outside the site's folder).
- Alerts: webhook (and Telegram/Discord) notifications no longer connect to loopback, link-local (cloud metadata, 169.254.169.254) or unspecified addresses; addresses on private LANs stay allowed.

Update the agents on remote servers after updating the panel (Settings → Panel update → Agents): the account checks and backup downloads need the new agent.

Panels on v1.15.0 or older must update once by hand (see the v1.16.0 notes):
  curl -fsSLO https://raw.githubusercontent.com/bayurstarcool/SigardaPanel/main/install.sh
  sudo bash install.sh update

Install with the script in the repository README; every file is signed (see "Verifying releases").
