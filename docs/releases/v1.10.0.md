SigardaPanel v1.10.0

Security release: fixes from end-to-end testing and two full security audits. Update the panel, then the agent on every server.

Tenant isolation
- Each PHP site now runs in its own PHP-FPM pool as the site owner, with open_basedir, and site roots are owner:<nginx group> 2750. Another site's PHP, shell, cron job or SSH account can no longer read wp-config.php or .env files of other sites. Existing PHP sites move to their own pool automatically, a few at a time, once their server's agent runs this version.
- The root agent no longer follows symlinks a site owner plants in or above a site root (create, delete, backup, restore, file manager, disk usage, SSH accounts, git deploy). Git deploy runs as the site owner.
- App services no longer let a site's .env point at server secrets (it was read by systemd as root).
- Databases named after server schemas (mysql, sys, information_schema, postgres, template*) are refused, and an existing database is never taken over.
- Existing Linux accounts with sudo/docker/admin group membership, and SFTP jail accounts, are never used as site owners.

Roles: what changes for admins
- Managing servers (add, change, delete, terminal, command, Docker, firewall, fail2ban, Redis, Stack) is now super_admin only. Servers have no owner, so an admin could act as root on servers hosting other tenants.
- Docker sites, editing the raw nginx vhost and activating/removing the license are super_admin only.
- Admins keep managing their own sites, the users they created (including impersonation), site assignments, cron and suspend/resume.
- Staff who manage servers should be super_admin.

Agents
- Remote agents use TLS with a certificate pinned by the panel. New agents are installed with TLS; existing agents switch to TLS automatically after they are updated. The agent installer limits port 7710 to the panel's address when ufw is active.
- If a server's Linux account for a site owner has sudo (for example "admin" on Debian cloud images) and should own sites, add its name to /etc/sigardapanel/trusted-site-users on that server. The panel installer adds the super admin's name on the panel host.

Other fixes
- Backups: database dumps work again (MySQL dumps were skipped), "Files + Database" backups include the databases, restore no longer fails when /var/backups/sigardapanel is missing.
- Cross-site request protection for the web proxy and login; impersonation ends when the impersonating admin is demoted or removed; 2FA codes cannot be replayed; site transfers clear deploy settings; proxy sites cannot point at cloud metadata or local services; php.ini settings are limited to a safe list (others are dropped when the vhost is regenerated).
- nginx on hosts without IPv6, creating several sites at once, the Logs tab and new sites staying "Pending" until a reload.

Panels on v1.6.2 or older must update once by hand because of the new signing key (see the v1.7.1 notes):
  curl -fsSLO https://raw.githubusercontent.com/bayurstarcool/SigardaPanel/main/install.sh
  sudo bash install.sh update

Install with the script in the repository README; every file is signed (see "Verifying releases").
