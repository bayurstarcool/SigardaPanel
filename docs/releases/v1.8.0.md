SigardaPanel v1.8.0

A feature audit of the file manager, SSH, databases and the site pages, with the fixes and the missing pieces it found.

Database viewer (new)
- Databases › Browse opens a viewer for MySQL/MariaDB and PostgreSQL databases: tables with size and row estimates, column structure, rows with sorting and pages, and an SQL tab for queries.
- It runs on the database's own server with one of the database's own accounts (never root), so it works for sites on any server.
- It is read-only: only SELECT, SHOW, DESCRIBE and EXPLAIN are accepted, each request runs in a read-only transaction that is rolled back, and a query is a single statement. Results are capped at 500 rows.
- Opening it needs write permission on the site, like phpMyAdmin. Queries are recorded in the audit log.

Databases
- PostgreSQL works. The agent ran psql as root, which connects as a role that does not exist, so creating or deleting PostgreSQL databases and users failed. New users can also create tables (PostgreSQL 15+ closes the public schema to everyone but its owner).
- MySQL databases of sites on other servers were created on the panel host's MySQL. The panel's direct MySQL connection is now used only for sites on the panel host; other sites go through their server's agent. Operations that are not available yet for databases on other servers (changing a user's host or privileges, granting an existing account, character set changes, phpMyAdmin) say so instead of acting on the wrong server.
- The site Databases tab's "Auto" password works. PostgreSQL databases no longer get MySQL character sets. phpMyAdmin is offered for MySQL only.

File manager
- New: extract .zip archives, and change permissions (chmod).
- Listings are sorted (folders first). Symbolic links are marked, and links inside the site can be opened.
- Binary and non-UTF-8 files are downloaded instead of being opened in the editor, where saving corrupted them. Files with Windows line endings keep them.
- Large compress, extract, move and delete operations no longer fail after 30 seconds while finishing on the server.
- Folders can be selected; Move, Compress, Extract and Permissions are in the context menu; Ctrl+S saves; unsaved changes are confirmed before leaving; uploads over 32 MB get a clear message; a failed download no longer saves an error page as the file.

SSH / SFTP
- New accounts can log in on the panel host. Their jail mounts were made in the agent's private mount namespace and were invisible to sshd until a reboot.
- Accounts can write the site's files (they act as the site's Linux user, inside a chroot showing only the site at /htdocs), and the jail has /dev and /tmp for git, composer and php.
- Site owners and site writers manage their own accounts (it needed a global admin). Usernames can be chosen, private keys can be downloaded again and are stored encrypted.
- The SSH tab shows SFTP connection details (port 22, key file) instead of an FTP/ProFTPD card for a service that was never set up.

Terminal
- Reconnecting no longer types Enter into the shell. Idle terminals are kept alive.
- Leaving the shell (exit, Ctrl+D) ends the session instead of starting a new shell; a refused or unreachable terminal stops retrying; Disconnect ends the shell on the server.

Site pages and navigation
- Tabs follow the site's runtime: reverse proxies have no Databases, Cron, Files or SSH tab and no Git deploy; the App tab and app process controls only appear for app runtimes; PHP settings and PHP-FPM logs only for PHP sites.
- Buttons follow your permission on the site: Delete for the owner, Git deploy for site writers, Transfer for those allowed to, raw vhost editing for admins. The open tab is kept in the address (?tab=).
- Docker sites: the Logs and App tabs could match another site's container by a partial name; they use the exact container name now, and a rebuild keeps the name the panel expects.
- The sidebar and dashboard only show server tools (Docker, PM2, Redis, Email, Firewall, Bot Blocker, Threat Monitor, Terminal) to admins, since the API refuses them to other roles. Files moves to Hosting. Fail2ban is listed for admins.

Upgrade notes
- Update the agent on every server after upgrading the panel: the viewer, PostgreSQL, SSH, terminal and file manager changes run on the agent.
- SSH accounts created before this release keep their separate Linux user (read-only access to the site). Delete and re-create them to get write access.

Panels on v1.6.2 or older must update once by hand because of the new signing key (see the v1.7.1 notes):
  curl -fsSLO https://raw.githubusercontent.com/bayurstarcool/SigardaPanel/main/install.sh
  sudo bash install.sh update

Install with the script in the repository README; every file is signed (see "Verifying releases").
