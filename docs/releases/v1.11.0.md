SigardaPanel v1.11.0

Roles and permissions (RBAC).

- Every action in the panel is now checked against a named permission (for example site.cron, user.impersonate, server.terminal) instead of a role name. The three built-in roles keep exactly the access they had in v1.10.0: super_admin has every permission, admin manages its own sites and the users it created, user manages its own and assigned sites.
- Custom roles: a super admin can create roles under Settings -> Roles by combining permissions, for example a "support" role that can read every site and sign in as customers, but cannot change or delete anything. Users are given a custom role like a built-in one.
- Permissions that give root on a server or access to other tenants' data are marked "dangerous" and can only be granted by a super admin. Nobody can give a role or a user a permission they do not have themselves, and a role that holds user management still cannot touch accounts with more permissions than its own.
- Ownership still applies: a permission such as site.cron only works on sites the user owns or was assigned, unless the role also has an "all sites" permission.
- The web interface shows menus and buttons by permission, so custom roles see what they can use, and admins no longer see server controls they cannot use since v1.10.0.

API: GET /api/v1/rbac/permissions, GET/POST /api/v1/roles, PATCH/DELETE /api/v1/roles/:id; /api/v1/auth/me lists the caller's permissions.

Update the agent on every server after upgrading the panel.

Panels on v1.6.2 or older must update once by hand because of the new signing key (see the v1.7.1 notes):
  curl -fsSLO https://raw.githubusercontent.com/bayurstarcool/SigardaPanel/main/install.sh
  sudo bash install.sh update

Install with the script in the repository README; every file is signed (see "Verifying releases").
