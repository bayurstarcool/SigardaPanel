SigardaPanel v1.16.0

SvelteKit 3 and Node.js 22 for the web interface; the agent keeps the right to run commands as other accounts on hardened systemd hosts.

Panels on v1.15.0 or older must update once by hand (the one-click update of those versions cannot install Node.js 22; it fails and rolls back by itself, leaving the panel as it was):
  curl -fsSLO https://raw.githubusercontent.com/bayurstarcool/SigardaPanel/main/install.sh
  sudo bash install.sh update
Later updates work from the panel again.

Web interface
- Moved to SvelteKit 3 (with Vite 8 and adapter-node 6). SvelteKit 2 has no fix for the advisories GHSA-pfhg-q3qv-9q6r, GHSA-27mw-82g8-phjj, GHSA-3r8g-jcqq-3p5j and GHSA-6cf5-gc4q-fm3x (and cookie GHSA-pxg6-pf52-xh8x); the panel did not use the affected features, but the dependency audit is clean again.
- SvelteKit 3 needs Node.js 22.17 or newer. The installer and install.sh update install Node.js 22 from NodeSource when /usr/bin/node is missing or older (Ubuntu 24.04 ships 18), before anything else is changed; a newer Node.js that is already there (e.g. 24) is kept. Node.js apps of sites on the panel host that use the system Node.js then run on Node.js 22.
- On the panel host the Stack page no longer removes Node.js or installs a line older than 22 (the panel itself runs on it).

Agent unit
- With systemd 255, an agent unit that says User=root together with NoNewPrivileges and a seccomp option starts the agent without CAP_SETUID, so tasks that run a command as another account fail with "operation not permitted" (PostgreSQL through the postgres account, git deploys as the site owner, the site terminal, database restores). New installs no longer write User=root, and updating the panel or a remote agent replaces it in /etc/systemd/system/sigardapanel-agent.service with Environment=HOME=/root and reloads systemd before the agent restarts.

Update the agents on remote servers after updating the panel (Settings → Panel update → Agents).

Panels on v1.6.2 or older must first take the new signing key into account (see the v1.7.1 notes); the manual update above covers it.

Install with the script in the repository README; every file is signed (see "Verifying releases").
