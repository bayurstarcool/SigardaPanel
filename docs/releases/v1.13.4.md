SigardaPanel v1.13.4

External sites are never changed on the server.

- A site added with managed_by "external" (a vhost written by hand, or one domain of an application that serves several domains from the same folder, such as a multi-site CMS) is listed and monitored by the panel, but the panel no longer touches it on the server: no vhost regeneration (PHP, security, IP restrictions), no move to its own PHP-FPM pool, no certificate issue or renewal, no suspend, resume, deploy or transfer. Such jobs fail at once with "external site" and never reach the agent.
- Deleting an external site removes only its panel record. Its folder (often shared with other domains), vhost, certificate, databases and DNS records stay on the server, whatever the "delete files" choice.
- Sites created by the panel and CloudPanel imports work as before.

Update the agents on remote servers after updating the panel (Settings → Panel update → Agents).

Panels on v1.6.2 or older must update once by hand because of the new signing key (see the v1.7.1 notes):
  curl -fsSLO https://raw.githubusercontent.com/bayurstarcool/SigardaPanel/main/install.sh
  sudo bash install.sh update

Install with the script in the repository README; every file is signed (see "Verifying releases").
